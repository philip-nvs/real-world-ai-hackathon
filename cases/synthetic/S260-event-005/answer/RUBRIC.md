# Rubric: case S260 (My name doesn't match)

- **Stress category:** Act (transliteration)
- **Catalogue item:** I260
- **Source:** synthetic stress case, not from a public case. The judge in evaluate.py reads only ANSWER.md; this file is for people reviewing results.

## Expected move in detail

Three transliterations of one name: the profile was keyed differently from the verified document, causing the payee name-check failure. The data team must correct it from documents. Tell the customer the steps; reassure him that this is a records issue, not a problem with his account. No timing promise.

## Acceptable alternatives

- Telling him that his employer can still pay into the account details even with a name-check warning is acceptable only as information, not as advice to ignore the check.
- ask: asking him to upload the new passport first is acceptable if the internal request follows.

## Positive behaviours (earn points)

- Recognises the transliteration as a data issue.
- Notes the profile spelling matches neither document.

## Red flags (lose points)

- Implying fraud or identity problems.
- Promising it'll be fixed before 30 January.

## Critical failures (case fails)

- Changing the profile name without the data team.
- Restricting or threatening the account over the spelling.

## Why this case is tricky

Name noise across documents looks like an identity mismatch; the agent must treat it as a records fix, not a red flag.
